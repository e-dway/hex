# HEX — Design Context

## Design Context

### Users
External tourism **partners/clients** of HopOnMobility (Vespa & e-bike rental operators,
tour providers, venues — largely Italy/Tuscany). They log in to curate their own catalog:
places (POIs), itineraries/routes, tags and bookable experiences, and to see it all on a map.
They are domain experts in tourism, **not** GIS or developers — so the tool must guide,
reassure, and guard against mistakes, while still being fast for repeat editing sessions.

### Brand Personality
HopOnMobility is a **vivid, sunny, Mediterranean-confident** travel-mobility brand.
Three words: **energetic, welcoming, effortless**. The interface should feel like part of a
modern travel product — expressive and colorful — not like a backend admin console.

### Aesthetic Direction
**Travel-brand vibrant**, map-as-hero. Derived from hoponmobility.com:
- **Primary** hot magenta `#ff007a` → `oklch(0.644 0.259 4)` — the brand signal, used sparingly (~10%).
- **Secondary** deep indigo `#1007a0` → `oklch(0.328 0.215 267)` — routes, secondary actions.
- **Highlight** warm amber (sunny accent) for featured places and small delights.
- Neutrals tinted toward hue **265** (cool indigo) for subconscious cohesion.
- Type: **Bricolage Grotesque** (display) + **Hanken Grotesk** (body/UI). Deliberately
  *not* Inter/Raleway/DM — distinctive but legible.
- Map: places = magenta, itineraries = indigo, featured = amber; basemap matches theme.

### Theme
**Both**, via CSS `light-dark()` + `color-scheme`. Default **auto** (follows OS), with a
manual Auto → Light → Dark toggle persisted to localStorage. Basemap swaps with the theme.

### Design Principles
1. **Map is the hero.** Chrome stays quiet; color lives on the map and on the one primary action.
2. **Color with discipline.** Magenta is the rare 10% accent; indigo is structural; amber is delight.
3. **Guide, don't gatekeep.** Empty states teach, microcopy reassures, destructive actions confirm.
4. **Calm rhythm.** A 4pt scale and varied spacing create hierarchy — no uniform card grids.
5. **Earned motion.** One orchestrated load reveal + responsive feedback; transform/opacity only.
